# Проект: Tauri-клиент для Status (Sidecar-архитектура)

## Суть проекта
Разработка легковесного десктопного клиента-альтернативы `status-desktop` на базе Tauri (Rust + Svelte 5) с использованием Tailwind CSS.

Взаимодействие с бэкендом Status реализовано по **Варианту A (Sidecar)**:
Вместо сложной и проблемной линковки Go-библиотеки `libstatus` (Вариант B) напрямую в Rust-процесс, мы используем скомпилированный бинарник `status-backend` как внешний процесс (sidecar).

### Архитектура и поток данных
1. **Бэкенд (Nix-окружение):** Запускается скомпилированный в Nix бинарник `status-backend`. Он слушает HTTP и WebSocket порты.
2. **Транспорт:**
   - **WebSocket (`ws://localhost:12345/signals`)**: Используется для получения событий (сигналов) в реальном времени от бэкенда (например, `mediaserver.started`, `node.ready`, `node.login`).
   - **HTTP (`http://localhost:12345/statusgo/...`)**: Используется для вызова RPC-методов (инициализация приложения, создание аккаунта, логин и т.д.).
3. **Фронтенд (Tauri + Svelte 5):**
   - Tauri предоставляет WebView с приложением на Svelte 5.
   - Для WebSocket используется плагин `@tauri-apps/plugin-websocket` (вызовы идут через Rust-ядро Tauri).
   - Стейт-менеджмент построен на рунах Svelte 5 (`$state`, `$props`).
   - Вёрстка стилизована с помощью Tailwind CSS (v4).
